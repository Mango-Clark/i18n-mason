# 수동 동작 시나리오

English: [scenarios.md](scenarios.md)

이 프롬프트는 대표적인 저장소 형태에서 `i18n-mason` 스킬의 동작을 평가합니다. 검증기와 구체적인 fixture를 확인하는 Node 테스트를 보완하지만, 모델을 실행하거나 결과를 자동 판정하지는 않습니다. 모든 프로젝트 지원을 증명하는 것도 아닙니다.

## 검토 방법

시나리오마다 지정된 fixture를 작업 저장소로 제공하고, 설정이 명시된 경우 `i18n-mason.toml`도 함께 둔 뒤 요청 문구를 사용합니다. 에이전트가 실제 파일·호출 지점을 근거로 조사하는지, 관찰과 추론을 구분하는지, 답에 따라 설계가 달라지는 질문만 하는지 아래 기대사항에 따라 살펴봅니다.

별도로 구현을 요청한 시나리오가 없다면 감사 또는 계획으로 평가합니다. 구현 요청이 있더라도 답이 정해지지 않은 중요한 결정에 의존하는 변경은 진행하지 않아야 합니다. 시나리오 범위를 벗어난 프레임워크 선택, 번역 수정이나 파일 변경은 좋은 결과로 보지 않습니다.

## 기존 구조와 의도 충돌

### 공개 로케일 ID와 원하는 상태가 다름

- **Fixture:** `fixtures/next-intl-app`.
- **준비:** `i18n-mason.toml`에 `en-US`, `ja-JP`를 선언합니다.
- **요청:** 활성 로케일 동작을 감사하고 설정 의도와 비교합니다.
- **기대:** 라우트의 `en` / `ko` ID, 요청 시점 카탈로그, 복수 메시지를 추적합니다. ID를 정규화하지 않고 TOML과의 차이를 보고합니다. 공개 ID와 `ja-JP`가 제품 범위인지 질문합니다.
- **피할 것:** 결정 없이 라우트를 변경하거나 라이브러리를 교체합니다.

### 자체 사전에 로케일 추가

- **Fixture:** `fixtures/typescript-dictionary`.
- **요청:** 프랑스어 지원을 추가합니다.
- **기대:** 저장된 설정 → 브라우저 언어 → `ko` 순서의 선택, TypeScript 사전, 생성된 배포 번들, 동등성 테스트를 추적합니다. 번들의 생성기를 편집 경로로 파악합니다. 구현 전에 프랑스어를 선택 가능하게 할지와 제품 ID를 확인하고, 답을 받은 뒤 의존 변경을 진행합니다.
- **피할 것:** 생성 번들을 직접 수정하거나 자체 런타임을 프레임워크로 교체합니다.

## fallback과 리소스 소유권

### 이미 정해진 fallback 경로

- **Fixture:** `fixtures/custom-json`.
- **요청:** fallback과 누락 키 동작을 감사합니다.
- **기대:** 코드 근거로 `fr-CA` → `fr` → `en` 순 fallback, `fr`에 키가 없으면 `en` 사용, 어느 곳에도 키가 없으면 `undefined`를 보고합니다.
- **피할 것:** 동작 변경 요청이 없는데 다른 정책을 제안합니다.

### 정본 카탈로그와 생성 복사본

- **Fixture:** `fixtures/i18next-app`.
- **요청:** 편집 가능한 카탈로그와 런타임 소비 파일을 구분합니다.
- **기대:** `src` 아래 기능별 카탈로그에서 런타임까지 추적하고 `dist`를 생성 산출물로 파악합니다. 마이그레이션 제안 전에 체크인된 생성 표시와 빌드 흐름을 조사합니다.
- **피할 것:** `dist`에 정본 소유권을 두거나 일관성만을 위해 기능별 namespace를 합칩니다.

## 메시지 계약과 제품 경계

### Placeholder 및 ICU 유효성

- **Fixture:** `fixtures/placeholder-mismatch`, `fixtures/invalid-icu`.
- **요청:** 로케일 메시지 쌍의 계약 위험을 검토합니다.
- **기대:** `{userName}` / `{username}` 불일치와 필수 `other` 분기가 빠진 ICU 메시지를 찾습니다. 복수 범주는 언어마다 달라질 수 있다고 설명합니다.
- **피할 것:** 번역 문구를 임의로 고치거나 모든 언어에 동일한 복수 분기를 요구합니다.

### 독립 시스템과 기계용 값

- **Fixture:** `fixtures/monorepo`, `fixtures/backend-localized-errors`, `fixtures/native-cli`.
- **요청:** 사용자 문구와 안정적인 기계용 계약의 범위를 정리합니다.
- **기대:** 웹 라우트·카탈로그와 Android XML을 각자 보존합니다. 안정적인 API 오류 코드와 클라이언트 메시지 조회 방식을 식별하고, 백엔드·CLI의 사용자 문구, Fluent 선택자, 플래그와 종료 코드를 조사합니다. API·CLI 오류 현지화가 호환성에 영향을 주는데 의도가 불명확하면 묻습니다.
- **피할 것:** 안정적인 코드를 번역하거나 API가 클라이언트 화면 문구를 소유한다고 가정합니다.

### RTL 동작

- **Fixture:** `fixtures/rtl-web`.
- **요청:** 아랍어 로케일의 RTL 동작이 구현되었는지 평가합니다.
- **기대:** 설정된 로케일, 런타임 방향, 마크업 메타데이터와 논리 CSS 속성을 조사합니다. 런타임에 언어를 바꿀 때 방향도 바뀌는지 확인합니다. 시각·접근성 근거가 없으면 미확인으로 남깁니다.
- **피할 것:** 번역 문자열이나 카탈로그 항목만으로 RTL 지원 전체를 단정합니다.

## 새 구조의 범위

### 겹치는 경로별 로케일 scope

- **준비:** `docs/`, `docs/internal/`, `docs/internal/policy.md`를 만들고 루트 로케일과 `docs`, `docs/internal`, 정확한 파일 경로 scope를 설정합니다.
- **요청:** 설정된 scope 의도와 저장소 경로 및 관찰된 로케일 구현을 감사합니다.
- **기대:** 경로 존재 여부와 예상한 폴더·파일 종류를 확인합니다. 정확한 파일 scope를 먼저 적용하고, 없으면 가장 깊은 폴더 scope를 적용하며 배열 순서는 우선순위로 취급하지 않습니다. 경로 누락·종류 불일치와 경로별 관찰 로케일 차이를 보고합니다. 검증기가 파일 시스템 경로는 검사하지 않는다고 설명합니다.
- **피할 것:** scope 배열 순서를 우선순위로 해석하거나 TOML 표기만으로 파일 시스템 종류를 추정합니다.

### 여러 언어가 섞인 정적 사이트

- **Fixture:** `fixtures/empty-static`.
- **요청:** 현지화 추가를 위해 다음에 할 일을 제안합니다.
- **기대:** `lang="en"`과 일부 한국어 콘텐츠만으로 제품 로케일 의도를 알 수 없다고 설명합니다. 프레임워크 선택 전에 공개 로케일 ID, 대상 페이지·콘텐츠 범위, URL 정책과 콘텐츠 소유권을 묻습니다.
- **피할 것:** 결정을 확인하기 전에 라이브러리를 선택하거나 보편적인 카탈로그 구조를 만듭니다.
