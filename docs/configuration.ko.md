# `i18n-mason.toml` v1

English: [configuration.md](configuration.md)

저장소 루트 설정은 구현 방식과 분리된, 지원하려는 로케일 의도입니다. 프레임워크와 런타임 세부 사항은 코드베이스에서 발견합니다.

```toml
version = 1
default_locale = "ko-KR"
locales = ["ko-KR", "en-US", "ja-JP"]
```

## 스키마

| 키 | 형식 | 필수 | 의미 |
| --- | --- | --- | --- |
| `version` | 정수 | 예 | 스키마 버전. v1은 `1`만 허용합니다. |
| `default_locale` | 비어 있지 않은 문자열 | 예 | 의도한 기본 로케일. `locales`에 정확히 포함되어야 합니다. |
| `locales` | 서로 다른 비어 있지 않은 문자열의 배열 | 예 | 제품 로케일 식별자. 표기와 순서를 유지합니다. |

검증기는 일반 공백, 전체 줄 및 줄 끝 주석, 이스케이프되지 않은 큰따옴표 문자열, 한 줄 또는 여러 줄 로케일 배열을 허용합니다. 키·로케일 중복, 알 수 없는 항목, 필수 값 누락, 빈 값, 지원하지 않는 버전은 거부합니다. 로케일 태그를 정규화하거나 문법으로 제한하지 않습니다. 외부 공개용 또는 레거시 식별자일 수 있으므로 코드베이스에서 의미를 확인해야 합니다. 이스케이프 문자열과 일반 TOML 테이블은 이 작은 v1 범위에 포함되지 않습니다. 세 루트 키만 사용하세요.

```sh
npm run validate
node scripts/validate-config.mjs path/to/i18n-mason.toml
```

설정 검증이 리소스 범위, 라우팅, 번역 품질 또는 런타임 지원을 증명하지는 않습니다. 프로젝트별 근거와 검사가 필요합니다.

## 원하는 상태와 관찰한 상태

이 파일을 원하는 로케일 상태로 취급하고, 코드·리소스·테스트·라우트·생성 스크립트·문서를 조사해 실제 동작을 확인합니다. 차이가 있으면 한쪽을 조용히 덮어쓰지 말고 보고합니다. 레거시 식별자, 별도 모노레포 범위, 생성·환경별 설정, 진행 중인 마이그레이션인지 살펴봅니다. 근거로 의도를 알 수 없다면 사용자에게 묻습니다.

이 저장소에서 루트 로케일 계약은 설명 문서에 적용됩니다. 영어(`en-US`)가 정본이며 한국어(`ko-KR`)는 짝을 이루는 문서로 관리합니다. 런타임 스킬은 범위를 정해 영어로만 유지합니다. 코드, 테스트와 기계가 사용하는 파일은 이 문서 로케일 집합에 포함되지 않습니다.
