# 아키텍처 조사와 결정

English: [discovery.md](discovery.md)

이 문서는 i18n-mason이 대상 저장소를 조사하고 판단하는 방법을 설명합니다. 일반적인 라이브러리 선택 안내서는 아닙니다.

## 근거 수집

실제 사용 흐름을 추적합니다. 소스 import와 호출 지점, 프레임워크 설정, 실제로 가져다 쓰는 의존성, 리소스 카탈로그, 라우트·미들웨어, 로케일 선택 코드, 계정·세션·쿠키·브라우저 설정, 메시지 제공자, 빌드·생성 스크립트, CI·배포, 테스트와 문서를 살펴봅니다. 의존성이나 파일의 존재만으로 런타임 동작을 단정하지 말고 소비 지점으로 확인합니다. 생성 주석, ignore 설정, 스크립트와 CI를 살펴 소스 파일과 산출물을 구별합니다.

모노레포에서는 앱과 패키지를 먼저 별도 시스템으로 조사합니다. 공통 디렉터리는 메시지 정의를 제공할 수 있지만 라우팅이나 런타임을 소유하지 않을 수 있습니다. 각 범위별 플랫폼, 메커니즘, 리소스 형식, 식별자, 정본, 소비자, 동작과 연결 관계를 기록합니다. 통합은 증거와 제품상 이점이 필요한 제안이지 기본값이 아닙니다.

리소스 형식에는 JSON/YAML/TS, gettext PO/POT, XLIFF, ARB, Fluent, ICU, Android/iOS 카탈로그, 데이터베이스, CMS/TMS와 생성 산출물이 있습니다. 의존성만으로 실제 사용이나 정본 여부를 확정할 수 없습니다. 입력에서 변환 과정을 거쳐 생성 파일과 런타임 소비자에 이르는 흐름을 확인합니다.

## 중요한 미결정 사항만 묻기

질문 정책은 정확한 구현을 위한 일부입니다. 충분히 조사한 뒤 관련 질문을 묶어서 합니다. 어떤 근거로 확인했는지, 무엇이 충돌하거나 불명확한지, 답변에 따라 무엇이 달라지는지 설명합니다. 사실과 추론을 구분하고 저장소에서 확인할 수 있는 내용을 다시 묻지 않습니다.

- 영향이 낮은 서식은 기존 규칙을 따릅니다.
- 중간 영향의 구조는 기존 규칙을 따릅니다. 선례가 없거나 새 공개 경계를 만들 때 질문합니다.
- 영향이 큰 동작은 저장소나 사용자 요구에서 확인되지 않으면 결정을 요청합니다. 로케일 식별자·기본값, 라우팅과 URL, 선택 순서, fallback 및 번역 누락 동작, 번역 정본, 공개 API 현지화 계약, TMS 도입, 통합·마이그레이션, UI 외 현지화 범위 등이 이에 해당합니다.

사용자 답변과 무관한 조사나 감사는 계속하되, 답변에 의존하는 동작 변경은 답을 받은 뒤 진행합니다. 적절한 프로젝트 규칙이 있다면 합의된 결정을 기존 문서에 남깁니다. 가치가 명확하지 않으면 무거운 ADR 절차를 만들지 않습니다.

## 발견할 런타임 구조

설정, URL, API, 데이터베이스, 사용자 설정, 카탈로그와 플랫폼 API 전반에서 로케일 식별자가 정확히 어떻게 쓰이는지 확인합니다. 명시적 설정, URL, 프로필·계정, 세션·쿠키, 브라우저·OS, 요청 헤더 또는 API 입력 중 무엇이 로케일을 고르는지 추적합니다. 우선순위는 근거 또는 사용자 결정 없이 정하지 않습니다. 웹에서는 리디렉션, 정규 URL, 딥링크, 언어 전환과 생성 링크도 확인합니다.

fallback 경로와 환경별 동작을 확인합니다. 개발, CI·빌드, 프로덕션에서 번역 누락 시 어떤 일이 발생하는지 조사합니다. fallback은 사용자 경험을 지키지만 누락을 숨길 수도 있습니다. 일반적인 기본값이라는 이유로 정책을 추측하지 않습니다. 공개 API, 저장 데이터, 캐시, 안정적인 오류 코드와 로케일의 관계도 확인합니다.

메시지 흐름마다 사용자에게 보이는 내용(UI·접근성·CLI·이메일·리포트·검증 오류 포함)과 기계가 사용하는 구문, ID, API 필드명, 경로와 프로토콜 데이터를 구분합니다. 문자열처럼 보인다는 이유만으로 분류하지 말고 주변 코드와 동작을 확인합니다.

번역 가능한 완결된 문장 단위를 유지합니다. placeholder, 형식, 이스케이프, ICU 복수·선택 구문, 리치 텍스트와 번역가 제어 마크업을 살펴봅니다. 형식에 맞는 파서로 메시지를 검사합니다. 복수 범주는 언어별로 다릅니다. 원문과 번역문에 동일한 분기 집합을 요구하지 말고, 각 언어에서 유효한지와 ICU `other`처럼 필요한 분기가 있는지 확인합니다. 날짜, 숫자, 통화, 목록, 정렬과 단위는 플랫폼 로케일 포맷터를 사용합니다. RTL이나 새 문자 체계가 관련되면 방향 메타데이터, 논리적 레이아웃, 혼합 방향 텍스트, 키보드·내비게이션, 폰트, 텍스트 확장과 접근성 근거를 확인합니다.

## 감사와 변경 경계

감사 결과에는 관찰된 시스템과 범위, 기본·지원 로케일, 소스·생성 흐름, 선택·라우팅·fallback·누락 동작, 검증 근거, 신뢰도와 맥락을 갖춘 하드코딩 문자열 후보, placeholder 위험, RTL 위험과 TOML 충돌을 포함할 수 있습니다. 확인된 사실, 추론, 미지 항목, 충돌과 권고를 구분합니다.

마이그레이션 전에 소비 지점, 정본, 키 계약, 런타임 fallback, 로케일 계약, 소유권, CI·배포 영향과 단계적 롤백 경로를 확인합니다. 기존 키와 동작을 보존하고 제거 대상임을 확인한 뒤에만 리소스를 삭제합니다. 번역 완성도뿐 아니라 구조도 검증합니다. 각 검사가 어떤 주장을 뒷받침하는지와 확인되지 않은 부분을 정확히 보고합니다.
