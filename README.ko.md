# i18n-mason

English: [README.md](README.md)

`i18n-mason`은 실제 코드베이스의 국제화(i18n) 구조를 이해하고 변경하기 위한 에이전트 스킬입니다. 아키텍처 감사, 로케일 추가, 구현과 마이그레이션에 활용할 수 있습니다. 번역 서비스나 프레임워크 설치 도구는 아닙니다.

핵심 원칙은 간단합니다. **구조를 고르기 전에 프로젝트가 실제로 어떻게 동작하는지 조사합니다.** 한 저장소 안에서도 앱마다 런타임, 카탈로그, 로케일 식별자와 배포 절차가 다를 수 있습니다. 스킬은 시스템별 경계를 추적하고, 기존 구조가 적절하면 그것을 확장합니다.

## 스킬 사용하기

이 저장소에서 사용자 전역 에이전트 스킬 디렉터리로 설치합니다.

```sh
npm run build
```

기본적으로 전체 스킬이 `~/.agents/skills/i18n-mason`에 복사됩니다. Windows에서는 사용자 프로필 아래에 설치됩니다. 특정 프로젝트의 `.agents` 디렉터리에 설치하려면 경로를 지정합니다.

```sh
npm run build -- --project ../my-app
```

PowerShell에서는 스크립트 인자를 전달할 수 있도록 npm 명령 shim을 사용합니다.

```powershell
npm.cmd run build -- --project ..\my-app
```

설치 후 코딩 에이전트에게 `i18n-mason`을 사용하도록 요청하고 작업을 설명합니다. 예를 들면 다음과 같습니다.

- “이 저장소의 로케일 선택과 fallback을 감사해 줘. 파일은 수정하지 마.”
- “프랑스어 지원을 추가해 줘. 먼저 현재 구현을 조사하고, 해결되지 않은 제품 결정을 질문해.”
- “생성 카탈로그 마이그레이션을 계획해 줘. 수정 전에 정본과 소비자를 밝혀 줘.”

감사 모드는 읽기 전용입니다. 구현과 마이그레이션은 저장소 규칙에 따르며, 코드 근거로 정할 수 없는 중요한 결정은 먼저 확인합니다.

### 설치본 갱신

설치기를 다시 실행해도 동일한 파일은 변경하지 않습니다. 패키지 파일이 설치본과 다르면 임의로 덮어쓰지 않고 중단합니다. 대상에 추가한 파일은 보존합니다. 차이를 검토한 뒤 패키지 파일을 교체하려면 다음 명령을 사용합니다.

```sh
npm run build -- --force
```

PowerShell에서는 `npm.cmd`를 사용합니다. 사용자 전역 `.agents` 디렉터리는 필요하면 자동 생성됩니다. `--project`로 이 저장소 안에 설치한 경우에는 로컬 `.agents/`가 Git에서 제외됩니다.

## 선택 사항: 로케일 의도 파일

제품에서 지원하려는 로케일을 명시해야 한다면 프로젝트 루트에 `i18n-mason.toml`을 만듭니다.

```toml
version = 1
default_locale = "en-US"
locales = ["en-US", "fr-FR"]
```

예시 값을 복사하기보다 제품에서 실제 사용하는 식별자를 적으세요. 선택 사항인 `[[scopes]]` 레코드로 저장소 경로별 루트 로케일 대체 목록을 지정할 수 있습니다. 프레임워크, 라우트, 리소스 형식, fallback 또는 런타임 동작은 설정하지 않습니다. 그런 정보는 코드베이스에서 조사합니다. 스킬은 설정과 관찰된 동작의 차이를 보고하며 어느 한쪽도 조용히 덮어쓰지 않습니다. [v1 설정 안내](docs/configuration.ko.md)를 참고하세요.

## 작업 진행 방식

1. **조사:** 저장소 지침과 로케일 의도를 읽고 런타임 코드, 소비 지점, 정본 카탈로그, 생성 산출물, 테스트, 배포 설정을 추적합니다.
2. **정리:** 관찰된 사실, 추론, 미지 사항과 충돌을 구분합니다. 모노레포는 앱·서비스별로 나누어 살펴봅니다.
3. **결정:** 사용자 동작, 호환성 또는 리소스 소유권에 실질적인 영향을 주면서 근거로 결정할 수 없는 항목만 묻습니다.
4. **변경 또는 보고:** 합의된 프로젝트별 변경을 적용하거나 읽기 전용 감사 결과를 제공합니다.
5. **검증:** 관련 동작을 입증하는 검사를 실행하고 확인되지 않은 항목을 함께 보고합니다.

조사 방법은 [아키텍처 조사 안내](docs/discovery.ko.md)에, 인수 예시는 [수동 시나리오](tests/scenarios.ko.md)에 있습니다.

## 전제하지 않는 것

- 특정 프레임워크, 프로그래밍 언어, 번역 라이브러리, 카탈로그 형식 또는 디렉터리 구조.
- 의존성이나 카탈로그 파일이 실제로 사용 중이며, 편집 가능한 정본이고, 지원 범위를 완전히 나타낸다는 가정.
- `en`, `en-US`, `en-GB` 같은 로케일 식별자가 서로 바꿔 쓸 수 있다는 가정.
- 모노레포의 공용 카탈로그가 앱 간 라우팅이나 런타임도 공유한다는 가정.
- 제품 근거 없이 fallback, 번역 누락 동작 또는 UI 외 현지화 범위를 결정하는 것.

이 원칙은 구조가 다른 프로젝트에도 스킬을 적용할 수 있게 합니다. fixture와 테스트는 조사 방법의 예일 뿐이며, 대상 프로젝트의 실제 동작은 그 저장소에서 확인해야 합니다.

## 이 저장소 개발과 검증

Node.js 23.6 이상이 필요합니다. 런타임 의존성은 없으며 Node 내장 기능만 사용하는 검사는 오프라인으로 실행할 수 있습니다.

```sh
npm test
npm run validate
node scripts/validate-config.mjs path/to/i18n-mason.toml
```

검증기는 scope 구문을 포함한 작은 v1 TOML 계약만 확인하고 실제 경로는 검사하지 않습니다. scope를 사용하는 프로젝트에는 업데이트된 검증기와 스킬이 필요하며 기존 v1 프로젝트는 마이그레이션할 필요가 없습니다. 대상 앱의 로케일 범위, 메시지 정확성, 라우트 또는 런타임 동작을 증명하지는 않습니다. 자동 테스트는 서로 다른 구조의 예시 fixture를 살펴보며, 에이전트를 직접 실행하거나 모든 프레임워크를 지원함을 증명하지 않습니다. 에이전트 동작을 평가하는 수동 시나리오는 `tests/scenarios.ko.md`에 있습니다.

이 저장소의 `i18n-mason.toml`은 설명 문서의 로케일 계약입니다. 영어(`en-US`)가 정본이고 한국어(`ko-KR`)는 짝을 이루는 문서로 관리합니다. `skills/i18n-mason/SKILL.md`에는 영어 전용 scope를 명시합니다. 코드, 테스트와 기계가 사용하는 파일은 이 문서 범위에 포함되지 않습니다.

## 저장소 안내

- `skills/i18n-mason/SKILL.md` — 코딩 에이전트가 읽는 지침.
- `docs/discovery.ko.md` — 근거 기반 조사 및 결정 절차.
- `docs/configuration.ko.md` — v1 로케일 설정 스키마와 검증 범위.
- `tests/fixtures/` — 서로 다른 i18n 구조를 보여주는 작은 코드베이스.
- `tests/scenarios.ko.md` — 에이전트 동작을 평가하는 수동 인수 시나리오.
- `scripts/install-skill.mjs` — 프로젝트별 경로로도 지정할 수 있는 사용자 전역 스킬 설치기 (`npm run build`).
- `scripts/validate-config.mjs` — 오프라인 v1 설정 검증기.
