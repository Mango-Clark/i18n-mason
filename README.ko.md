# i18n-mason

English: [README.md](README.md)

`i18n-mason`은 기존 또는 신규 코드베이스의 국제화(i18n) 구조를 발견하고, 설계하고, 구현·마이그레이션·검증하는 프레임워크 중립 에이전트 스킬입니다. 단순 번역기가 아니라 프로젝트에 맞는 국제화 구조를 세웁니다.

특정 프레임워크, 파일 형식, 라이브러리, 프런트엔드만을 전제하지 않습니다. 실제 코드와 런타임 동작에서 출발해 번역의 소유권과 사용 경계를 추적하고, 기존 구조가 적절하면 그대로 확장합니다. 일관성을 위해 동작 중인 시스템을 교체하지 않습니다.

## 질문하는 이유

기본 언어, 외부에 노출되는 로케일 식별자, URL, 대체 언어(fallback), 현지화 범위와 번역 소유권은 사용자 경험과 호환성에 영향을 줍니다. 저장소에 답이 있으면 그 근거를 따릅니다. 근거가 없으면 임의로 결정하지 않고, 확인된 사실·추정·충돌을 구분한 뒤 구현을 바꾸는 데 필요한 질문만 묶어서 합니다. 저장소가 이미 정한 서식이나 규칙은 사용자에게 되묻지 않습니다.

## 프로젝트에 설치하기

이 저장소에서 다음 명령을 실행하면 현재 프로젝트의 `.agents` 디렉터리에 스킬을 설치합니다.

```sh
npm run build
```

스킬은 `.agents/skills/i18n-mason`에 복사됩니다. 다른 프로젝트를 대상으로 하려면 경로를 지정하세요.

```sh
npm run build -- --project ../my-app
```

PowerShell에서는 npm이 인자를 스크립트에 전달하도록 명령 shim을 명시하세요.

```powershell
npm.cmd run build -- --project ..\my-app
npm.cmd run build -- --project ..\my-app --force
```

명령은 이후 추가될 references나 assets를 포함해 스킬 디렉터리 전체를 복사합니다. 다시 실행해도 설치본이 같으면 변경하지 않습니다. 기존 설치 파일이 패키지 파일과 다르면 로컬 변경을 덮어쓰지 않고 중단합니다. 패키지 파일을 교체하려면 `npm run build -- --force`를 사용하세요. PowerShell에서는 `npm.cmd run build -- --force`를 사용합니다. 대상의 추가 파일은 보존합니다. 생성된 `.agents/` 디렉터리는 Git에서 제외됩니다.

설치된 스킬은 로케일 구조 감사, 새 로케일 추가, i18n 구현 또는 마이그레이션에 사용합니다. 감사 모드는 읽기 전용입니다. 구현 모드는 저장소 규칙을 따르며, 해결되지 않은 중요한 결정을 구현하기 전에 확인합니다.

## 로케일 의도 설정

프로젝트 루트에 `i18n-mason.toml`을 둡니다.

```toml
version = 1
default_locale = "ko-KR"
locales = ["ko-KR", "en-US", "ja-JP"]
```

이 파일은 원하는 로케일 상태를 선언하며 프레임워크 설정을 복제하지 않습니다. 라이브러리, 라우팅, 리소스 형식, 디렉터리 또는 fallback 정책은 선언하지 않습니다. 실제 구현을 파악하는 우선 근거는 저장소입니다. 설정과 관찰된 동작의 차이를 조용히 덮어쓰지 않고 드러냅니다. [v1 스키마](docs/configuration.ko.md)를 참고하세요.

## 일반적인 작업 흐름

1. `i18n-mason.toml`에 로케일 의도를 추가하거나 확인합니다.
2. 저장소를 조사하도록 i18n-mason을 호출합니다.
3. 관찰한 구조와 번역 소스·생성 흐름, 설정과의 충돌을 보고합니다.
4. 설계에 실질적인 영향을 주며 저장소만으로 해결할 수 없는 결정을 묻습니다.
5. 결정이 정리되면 필요한 부분만 구현하거나 읽기 전용 감사 결과를 제공합니다.
6. 프로젝트에 맞는 동작을 검증하고 근거와 남은 불확실성을 보고합니다.

질문은 의도적이고 선별적입니다. 코드 조사를 사용자에게 맡기지 않습니다.

## 설계 원칙

- 실제 동작은 의존성 목록만으로 단정하지 않고 코드, 소비 지점, 테스트, 문서, CI 및 배포 설정을 교차 확인합니다.
- 모노레포의 앱과 서비스는 서로 다른 i18n 런타임과 리소스 구조를 가질 수 있습니다. 통합을 기본값으로 삼지 않습니다.
- `en`, `en-US`, `en-GB` 등 로케일 식별자는 의미가 다를 수 있으므로 임의로 치환하지 않습니다.
- 번역의 정본과 생성 산출물을 추적한 뒤 편집합니다.
- 사용자에게 보여주는 콘텐츠와 안정적인 API 필드, 식별자, 플래그, 경로 및 프로토콜 값을 구분합니다.
- placeholder, ICU 복수·선택 구문, 리치 텍스트 토큰을 계약으로 취급합니다. 날짜·숫자 형식과 RTL 지원은 실제 플랫폼 동작을 확인합니다.
- fallback, 번역 누락 동작, 라우팅, 로케일 선택 순서와 UI 외 콘텐츠의 현지화는 저장소에서 발견하거나 사용자와 결정합니다.

## 저장소 검증

Node.js 23.6 이상이 필요합니다. 런타임 의존성은 없습니다. 테스트와 설정 검증기는 Node 내장 기능만 사용하며 오프라인으로 실행할 수 있습니다.

```sh
npm test
npm run validate
node scripts/validate-config.mjs path/to/i18n-mason.toml
```

검증기는 v1 설정 구조를 확인합니다. 대상 앱의 번역 완성도, placeholder, 라우팅 또는 런타임 동작까지 증명하지는 않습니다. 그런 항목은 각 저장소에 근거한 별도 검증이 필요합니다.

이 저장소의 루트 설정은 패키지 설명 문서에 적용됩니다. 영어(`en-US`)를 정본으로 유지하고 한국어(`ko-KR`)는 짝을 이루는 문서로 관리합니다. `skills/i18n-mason/SKILL.md`는 의도적으로 영어만 사용합니다. 코드, 테스트와 기계가 사용하는 파일에는 문서 로케일 목록을 적용하지 않습니다.

## 구성과 한계

- `skills/i18n-mason/SKILL.md`: 실행 시 적용할 스킬 지침(영어).
- `docs/configuration.md`, `docs/discovery.md`: 영어 기술 문서.
- `docs/*.ko.md`: 한국어 기술 문서.
- `CONTRIBUTING.md`와 `CONTRIBUTING.ko.md`: 기여 안내.
- `tests/fixtures/`: 서로 다른 아키텍처를 보여주는 코드·리소스 fixture.
- `tests/scenarios.md`와 `tests/scenarios.ko.md`: 에이전트 동작 평가용 수동 시나리오.
- `scripts/validate-config.mjs`: 오프라인 설정 검증기.
- `scripts/install-skill.mjs`: `npm run build`에서 사용하는 프로젝트별 스킬 설치기.

자동 테스트는 웹 라우팅, 기능별 namespace, TypeScript 사전, 일반 JSON, gettext, Fluent CLI, ICU와 placeholder, fallback, 생성 파일, 서버·클라이언트 오류 현지화 경계, RTL 메타데이터, 혼합 모노레포의 fixture 코드를 확인합니다. 수동 에이전트 평가 시나리오도 함께 제공합니다. 이 fixture가 모든 프레임워크나 플랫폼을 지원한다는 뜻은 아닙니다. 실제 프로젝트에는 해당 플랫폼의 런타임 검증이 필요합니다.
